# 同频 · 通用课堂反馈 MVP

[English](README.en.md)

项目仓库：[bd4rex/tongpin-classroom-feedback](https://github.com/bd4rex/tongpin-classroom-feedback)。仓库为私有，克隆前需要相应的 GitHub 访问权限。

一个老师、一节当前课堂、很多学生现场加入。适用于数学、语文、英语、科学、人工智能等课程。音视频继续使用原有会议系统。

学生没有账号，也不需要提前导入名单。输入课堂码即可参与；昵称、学校和班级均为选填，未填写昵称时自动生成匿名编号。支持个人、小组、整班三种参与方式。

## 启动和试用

需要 Node.js 24 或更高版本。

```bash
git clone https://github.com/bd4rex/tongpin-classroom-feedback.git
cd tongpin-classroom-feedback
npm ci
npm run build
npm start
```

教师入口：`http://127.0.0.1:3210`；学生入口：`http://服务器IP:3210/join`。macOS 也可双击 `启动同频.command`。

1. 教师首次打开时设置一个管理密码，之后登录工作台。
2. 选择模板或创建空白课堂，分享课堂码或二维码。
3. 学生现场输入课堂码加入，不必填写个人资料。
4. 教师按组发布问题或任务。学生自行选择组内顺序，完成后进入已开放的后续组。教师查看整组进度、单题反馈和学生提问。
5. 结束课堂，回看记录或导出数据。历史活动可复用，历史回答不会带入新课堂。

服务器默认监听 `0.0.0.0:3210`。本机生成二维码时会尝试选取局域网地址；多网卡、VPN 或跨校网络请在 `.env` 中明确设置 `PUBLIC_URL`，并保证学生能访问该地址。复制 `.env.example` 为 `.env` 后，使用 `node --env-file=.env server/index.js` 启动。

## 已实现

- 一节当前课堂，以及结束后的历史记录；无学生管理、招生、学籍、作业或成绩系统。
- 单选、多选、判断、投票、理解度、开放回答、离堂反馈、AI 探究。
- 任务组创建与编辑、草稿任务移组；按组发布、暂停、继续、限时结束和手动结束。单题结果可分别显示／隐藏。
- 同一课堂可以同时开放多个任务组；发布后续组不会关闭前组，也不会把学生强制切换到新题。
- 按组查看已完成／进行中／未开始，支持按学生现场填写的学校、班级汇总。
- 学生自由切换任务，未提交的答案和 AI 提问草稿暂存在当前浏览器标签页，关闭标签页后不保证保留。
- SSE 实时通知和断线重连；实时连接异常时自动轮询。
- 提交数、提交率、答案分布、参考答案正确率、在线参与端、按自填学校／班级汇总。
- 学生向教师提问；其他学生看不到原文。
- CSV 回答导出，JSON 完整记录导出（活动、回答、问题、分析、AI 互动）。
- SQLite 持久化；浏览器刷新或服务器重启后可恢复已提交回答。

## 任务组如何使用

例如一节数学课分为“探索与练习”和“回顾与反思”两组。第一组可以同时包含两道选择题、一项开放任务，学生不必等待所有人完成同一道题。教师根据总体进度发布下一组，第一组默认继续开放；需要全体停下讨论时，教师可暂停相应任务组，或统一结束课堂。

“已完成”指该参与端提交了组内全部任务；“进行中”指打开过组内任务或已提交部分回答；“未开始”指尚无打开记录和回答。它表示页面参与情况，不推断真实学习状态。学校／班级均由现场选填，未填写的端归入“未填写”。

为了保持完成率的含义稳定，已发布组不再增加、删除或移动任务；临时补充练习可以新建一组。草稿组可自由编辑，默认由老师手动结束。升级前的逐题课堂会将每道原活动保留为独立组，不会意外公开旧草稿。

每个参与端每项活动提交一次；相同请求重试不会增加统计。以提交端为单位计算正确率和占比，**不把一个小组或一个班的回答折算为个人成绩**。更换浏览器、清除 Cookie 或使用新设备会成为新的匿名参与端，本版不解决身份核验或跨设备去重。

## AI 互动怎么开展

首版提供两个路径：

**学生探究**：教师添加“AI 探究”活动，写明任务及给模型的指令，设置每端最多 1–5 次提问。任务随所属任务组开放，时间由任务组统一控制。学生在任务范围内提问，阅读回答后提交评价或反思。每次为独立请求，需要在问题中补充上下文；不是无限多轮聊天。指令约束有助于维持教学主题，但不保证模型永远遵循主题。

**教师分析**：对于开放回答、离堂反馈和 AI 探究反思，教师主动点击“AI 辅助分析”。最多取 80 份、16,000 字样本，生成主要观点、需要核实的误解和后续追问。界面标明样本量与后续新增回答。昵称、学校、班级字段不会发送给模型；回答文本本身由学生填写，仍可能包含个人信息。

在“AI 设置”填入 OpenAI-compatible API 地址、模型名称和密钥。支持无密钥的本地模型；密钥保存在服务端 `data/model-config.json`，文件权限为 `0600`，不回显到浏览器。更换地址时需要重新填写或清除旧密钥，避免误发给其他服务。

保存设置不调用模型。点击“测试连接”、发布任务后学生提问、点击分析按钮，才会调用服务。自动化测试和本机容量验证使用模拟模型。首次部署后需要自行配置模型，并进行真实模型验证；现有测试不能代表真实模型答案质量或容量。

## 并发控制

| 普通反馈                                  | AI 请求                                      |
| ----------------------------------------- | -------------------------------------------- |
| 提交直接写入数据库，不调用模型            | 先入有界队列，再调用模型                     |
| 教师通知每 350ms 合并一次                 | 默认最多 4 个处理中、100 个等待              |
| 提交只通知教师，不向所有学生广播          | 每端同时最多一条请求                         |
| 只有发布、暂停等课堂控制通知全体学生      | 每项任务每端 1–5 次，服务端校验              |
| 汇总缓存 800ms；常规只返回最近 100 份回答 | 单次提问最多 1500 字，输出默认最多 600 Token |
| 学生每 25 秒心跳，75 秒内视为在线         | 单请求超时 25 秒，无自动付费重试             |

队列满时返回可重试提示，未接收的请求不扣次数。已接收的尝试计入额度，包括失败或取消的请求。暂停、结束任务组后，组内尚未派发的请求取消；已经发往模型的请求允许完成并保存结果。重启后，中断的请求会标记失败，不自动再次调用模型。

模型配置的同时处理数可设为 1–16，队列上限 1–200。教师分析和连接测试不会与学生任务同时争用队列；有未完成学生请求时提示稍后重试。一次分析／连接测试期间，学生新请求提示稍后重试。

容量应分别看“接入并提交反馈”和“同时使用模型”。本机 3000 端测试成功不表示能让 3000 个模型请求同时执行。正式试课前，应根据模型服务配额与实测延迟设置并发，可分批开放探究或采用小组终端参与。

## 校内服务器部署

直接运行上述 Node 命令即可。单实例运行，完整备份 `data/`。如果在线备份，请使用 SQLite Backup API；最简单的备份方式是先停止服务再复制整个目录，包括 WAL 文件。

也提供 Docker 配置：

```bash
docker compose up -d --build
```

Docker 的数据位于持久卷 `tongpin-data`。按实际情况设置 `PUBLIC_URL`。如使用 Nginx 反向代理，参考 `deploy/nginx.conf.example`；SSE 必须关闭代理缓冲。HTTPS 后设置 `COOKIE_SECURE=true`。

这是单服务器、单 Node 进程的 MVP。AI 调度器和通知订阅保存在进程内，SQLite 存储课堂记录。**不可直接启动多个实例共享数据库来扩容**；跨实例需要引入共享队列、发布订阅和共享数据库，并重新验证。尚未做公网部署、正式服务器实测或真实模型容量测试。
