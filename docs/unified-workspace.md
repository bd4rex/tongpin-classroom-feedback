## 借鉴 QuickForm 的哪些机制

参考 [QuickForm 官方仓库](https://github.com/wstlab/quickform) 的“任务 → 数据回收 → 查看与分析 → 导出复用”流程；具体对照本机教师版 2.0 的 `create_task`、`task_detail`、`submit_form`、`export_data` 与任务导入实现（本机参考仓库 HEAD 为 `6b1557568de75735732e94d6cc0b094ecc28c33f`）。官方仓库当前 README 已列出更新版本，因此这次不把本机 2.0 当成最新版本。

这次借鉴流程、独立实现；未复制或运行 QuickForm 源码，未连接 QuickForm 在线服务。

| 参考机制 | 同频中的落地 |
| --- | --- |
| 一个任务关联采集和结果 | 左侧选任务；右侧编辑、预览、发布所属组、看反馈与分析，默认不再区分课前／课中两个模式 |
| 已有资源可复用 | 原有“再上一节”复用整课；新“备课包”导出／导入一个教学环节，只复制内容 |
| 数据回收不必每次开发后端 | 导入的标准任务直接进入现有学生会话、校验、SSE 和统计路径，无需配置每题接口 |
| 先看数据，再分析 | 实时提交数、分布、学校／班级进度、原始回答与可选 AI 分析；按题导出 CSV |

QuickForm 的任意 HTML 附件、任意字段表单、公开收集 URL、跨域提交和在线任务迁移没有在本轮实现。现有 PPT、视频、交互实验仍可作为教学材料；本轮把它们对应的**问题、简短资源说明与反馈**纳入同频，不能直接上传任意网页执行。老师的模型配置、会话凭据、学生资料不进入备课说明或备课包。

## 教师如何节省备课时间

1. **上过相近的课**：先在“课后记录”点“再上一节”。需要先结束当前课堂；复制内容与采集设置，不复制学生及回答。
2. **只需要现场反馈**：点“快速备课”，选“课前摸底”“课中检查”或“离堂反馈”，核对预览后保存草稿。单个教学环节建议 2–4 项，避免每个资源都增加一张长问卷。
3. **已有教材或 AI 生成资源**：展开批量导入，填写本环节主题，复制备课说明，与课程材料一起交给常用 AI。将返回 JSON 粘贴回来，先校验与预览，再整组保存；也可以直接打开此前导出的 `.json` 备课包。此入口不直接调用真实模型，也不自动发送课程材料。
4. **发布前一次检查**：检查题意、选项和教师参考答案；用“学生视角预览”检查学生实际看到的材料。身份采集在“采集与展示”统一设置，只保留本节课确实需要的项目，并尽量在学生加入前确定。
5. **上课时一个入口**：分享课堂码或二维码，按教学环节“发布整组”。在同页选任务看反馈、疑问和统计；只有点击“展示本题结果”，学生和第二屏才能看到对应汇总。
6. **课后一次保存**：保存有用的教学环节为备课包，下一次直接导入；“导出本题反馈”保存当前任务的完整 CSV，“全课记录”保存含关联信息的完整 JSON。

所有导入内容先生成草稿。校验错误会指出第几项；单包 1–12 项，任务包请求体上限 256 KB（其余接口仍为 32 KB）；插入中途失败会整包回退。同一导入请求重试不会重复建组。成功后再次主动导入视为创建新的草稿副本。

## 学生怎样使用更合理

- 一次加入课堂，按教师设置填写必要信息；后续任务自动关联当前会话，不逐题填写学校、姓名或编号。
- 先看任务说明和简短材料，再作答。同一开放组内自行选择顺序；老师开放后续组不会强制切换当前题目。
- 未提交答案在同一浏览器标签页中暂存，切换题目、刷新可恢复；关闭标签页、清理浏览器数据或更换设备不保证恢复草稿。
- 提交成功明确显示“已保存”，再点“继续下一项”。每端每题一份反馈，网络重试不重复计数。
- 暂停时保留当前内容，可查看其他开放组；未公布的答案及其他学生原始回答不对学生展示。
- 理解度用于帮助老师决定是否再讲，开放回答用于说明依据，离堂反馈用于收集收获与疑问；不把点击次数或参与端数直接当作个人成绩。

## 回滚与备份

### 1. 只切回原界面

点击“切回原界面”，立即恢复“课前配置／课堂控制”布局。设置保存在当前浏览器；刷新保留。直接打开 `/?workspace=classic` 也可进入原布局，`/?workspace=unified` 返回统一布局。切换不写课堂数据，不结束课堂，不删除回答；这只是布局切换，后台仍是当前版本。

### 2. 保存当前数据快照

```bash
npm run backup
# 若使用自定义数据目录：
DATA_DIR=/absolute/path/to/data npm run backup
```

脚本通过 SQLite Backup API 一致性备份数据库，检查完整性和外键，备份数据目录中的模型配置及当前工作目录的 `.env`（存在时）。输出到 `output/backups/<时间>-<随机后缀>/`，附数量与 SHA-256 清单；目录权限 700、文件 600。此命令只创建副本，不恢复或覆盖现有数据。配置备份应与数据库一起妥善保存在本机；不要提交 GitHub。

- 原版本提交：`021bb8328558bf1d2a2f0921aa19ac087a220205`。

### 3. 回退应用代码，继续使用最新回答

本轮未修改数据库结构。需要恢复原程序时，先运行 `npm run backup` 保存**最新**数据，再停止当前同频进程。在独立目录运行回滚标签，保留当前数据目录：

```bash
# 在项目根目录执行；要求 output/rollback-app 尚不存在。
task_root="$PWD"
rollback_dir="$task_root/output/rollback-app"
git worktree add --detach "$rollback_dir" codex/pre-unified-feedback-20260920
cd "$rollback_dir"
npm ci
npm run build
DATA_DIR="$task_root/data" HOST=127.0.0.1 PORT=3210 npm start
```

如原服务使用其他数据目录、`.env`、`PUBLIC_URL`、端口或 Cookie 配置，沿用对应设置。不要同时运行新旧进程指向同一个课堂数据库。`source.bundle` 是本地代码备份，标签丢失时可以从中恢复原版本。

**普通代码回退无需覆盖数据库。** 用升级前的数据库替换最新数据库会丢失升级后收集的回答；只有确认数据损坏并确定恢复时间点后，才做完整数据恢复，同时保留被替换的数据库及 WAL/SHM。不要直接覆盖正在使用的 SQLite 文件。
